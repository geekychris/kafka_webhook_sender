create me a service that consumes events from kafka.  These events will be cloudevents and will have a "to" field.  The service is to be written in java springboot.  The service should store the records by "to" field along with some incrementing value to make each event unique.  Effectively the "to" should act as a way to create a number of virtual queues ordered by arrival but seperated by "to".  These events should be persisted in Rocksdb.  The service should keep a database of "subscribers" which contain the "to" as the key along with information like a URL to send these events as webhook events.  The subscription object should also support other delivery mechanisms if webhooks isnt chosen.  The system should keep track of each of these virtual queues and send outstanding events to the prescribed delivery method.  We will call this "sending".  The system will keep track of where it has got upto in sending and deliver events in order they arived to us.  If the send fails then the system should try again indefinitely with some reasonable backup.  The system must keep track of where it has successfully got up to so when it comes to attempt to send again it only will send those events not yet sent.  Keeping track of which things to send should be based upon the key order.  You can choose other methods of delivery other than webhooks.  The webhooks protocol should support cloudevent json batch format, so that one http request can send more than one event at a time.  Include a rest interface for managing the subscriptions and to monitor any interesting stats.  Include micrometer instrumentation so it can be monitored.  Include tests that include a local kafka, test events and a test webhook endpoint that can receive the traffic from the tests.
